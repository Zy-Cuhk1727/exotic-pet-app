The chat feature should build an app context before sending the user message. This helps the assistant answer based on the selected pet instead of giving generic reptile advice.

export function buildAppContext(selectedPet) {
  return {
    activePetId: selectedPet.id,
    activePetName: selectedPet.name,
    activePetSpecies: selectedPet.species,
    habitat: selectedPet.habitat,
    mood: selectedPet.mood,
    condition: selectedPet.condition,
    activity: `${selectedPet.activity}%`,
    metrics: selectedPet.metrics.map((metric) => ({
      label: metric.label,
      value: `${metric.value}${metric.unit}`,
      status: metric.status,
    })),
    alerts: selectedPet.alerts.map((alert) => ({
      title: alert.title,
      severity: alert.severity,
      message: alert.message,
    })),
    suggestedAction: selectedPet.action,
  };
}

The central relationship is Users to Pets. One user can own many pets, and each pet can have many sensor readings and alerts. AI chat sessions can optionally connect to a pet so previous advice can be reviewed later. Community and shop functions are connected to the user account.

Relationship Cardinality Purpose
Users to Pets One-to-many One owner can manage multiple exotic pets.
Pets to SensorReadings One-to-many Each pet has a history of monitoring readings.
SensorReadings to Alerts One-to-many / optional Abnormal readings can trigger alert records.

CommunityPosts to CommunityComments One-to-many Each community post can receive multiple comments.

The ERD can be organized into four clusters:

  • User and pet care cluster: Users, Pets, Subscriptions.
  • Monitoring and AI cluster: SensorReadings, Alerts, ChatSessions, ChatMessages.
  • Community cluster: CommunityPosts, CommunityComments.
  • Products and orders cluster: Products, Orders, OrderItems.

This clustering follows the user's journey: create a profile, add pets, monitor care, ask AI questions, participate in community, and optionally use shopping or premium features.
