【Final Product / 正文可截图：Table Definitions】

The schema comprises 12 tables, each supporting a specific ReptiMind feature. The table below lists the tables, their purposes, and representative fields.

Table Description Fields
Users Stores user account, preferences, notification settings, and personalization data. user_id PK, username, email UNIQUE, password_hash, preferred_unit, push_enabled, created_at
Pets Stores each reptile profile owned by a user. pet_id PK, user_id FK, name, species, habitat, condition_label, activity_score, suggested_action
SensorReadings Stores time-series monitoring data for temperature, humidity, UVB, activity, water, and soil readings. reading_id PK, pet_id FK, temperature_c, humidity_percent, uvb_uvi, activity_score, recorded_at
Alerts Stores abnormal condition warnings generated by sensor readings or pet status. alert_id PK, pet_id FK, user_id FK, title, message, severity, source, is_read
ChatSessions Stores AI chat sessions for each user and selected pet. session_id PK, user_id FK, active_pet_id FK, title, assistant_avatar_id, created_at
ChatMessages Stores user and assistant messages within a chat session. message_id PK, session_id FK, role, content, model_name, created_at
CommunityPosts Stores reptile community posts and optional linked pet profiles. post_id PK, user_id FK, pet_id FK NULL, title, body, image_url, like_count
CommunityComments Stores replies and discussion under community posts. comment_id PK, post_id FK, user_id FK, body, created_at
Products Stores reptile care products such as sensors, tanks, food, hides, and cameras. product_id PK, name, category, description, price, stock_quantity, is_active
Orders Stores user purchase records and order status. order_id PK, user_id FK, total_amount, order_status, payment_status, created_at
OrderItems Stores products included in each order. order_item_id PK, order_id FK, product_id FK, quantity, unit_price
Subscriptions Stores premium plan, billing status, and AI feature access settings. subscription_id PK, user_id FK, plan_name, price, status, ai_chat_limit, device_history_days

After defining all tables, we identified the major entity tables that carry the core business data of ReptiMind. These tables are the main bridge between the current app prototype and a future production database.

Major Entity Cluster Main Role in ReptiMind

【D2.2 Product Generation & Prompt Engineering / 正文可截图】

For the database schema deliverable, we used a three-step prompting process instead of asking AI for the whole schema at once. The process starts with table definitions, then refines relationships and major entities, and finally asks AI to reorganize the ERD into clear visual clusters.

【Prompt 1: Initial Table Definitions / 正文可截图】

We are app developers building an AI-powered exotic reptile care app called ReptiMind. Please design the first version of a production-ready relational database schema for the app.

Focus first on table definitions. The app should support users, reptile pet profiles, sensor readings, alerts, AI chat sessions, chat messages, community posts, community comments, shop products, orders, order items, and premium subscriptions.

For each table, provide its purpose, primary key, foreign keys, and representative fields. Do not create the ERD yet; start with the table design.

【AI Output 1: Table Definition Draft / Appendix 可截图】

The first schema draft should contain 12 tables. The tables can be grouped by business function: user and pet care, monitoring and AI, community, and shop/subscription features.

Users(user_id PK, username, email, password_hash, preferred_unit, push_enabled)
Pets(pet_id PK, user_id FK, name, species, habitat, condition_label, activity_score)
SensorReadings(reading_id PK, pet_id FK, temperature_c, humidity_percent, uvb_uvi, recorded_at)
Alerts(alert_id PK, pet_id FK, user_id FK, title, message, severity, source, is_read)
ChatSessions(session_id PK, user_id FK, active_pet_id FK, title, assistant_avatar_id)
ChatMessages(message_id PK, session_id FK, role, content, model_name)
CommunityPosts(post_id PK, user_id FK, pet_id FK NULL, title, body, image_url)
CommunityComments(comment_id PK, post_id FK, user_id FK, body)

OrderItems(order_item_id PK, order_id FK, product_id FK, quantity, unit_price)
Subscriptions(subscription_id PK, user_id FK, plan_name, price, status, ai_chat_limit)

【Explanation 1 / 正文可截图】

My goal in the first prompt was to convert the app features into database entities. I asked for table definitions before the ERD because the schema needed a stable list of tables and fields first. From this output, we kept the 12-table structure because it covered the final prototype features: pet profiles, monitoring data, alerts, AI chat, community, shop, and subscriptions.

【Prompt 2: Relationship Refinement / 正文可截图】

The initial table list is useful. Please refine it by adding relationship mapping, cardinality, and foreign key references.

Also identify the major entity tables that carry the core business data of ReptiMind. Separate core monitoring tables from future commercial expansion tables, so the schema can explain both the current prototype and future scaling.

【Explanation 2 / 正文可截图】

My goal in the second prompt was to make the schema more than a list of tables. I asked AI to define cardinality and foreign key references because the report needed to show how data integrity would be maintained. This refinement helped us produce the relationship mapping table and the major entity table summary.

【Prompt 3: ERD Refinement / 正文可截图】

Please generate a clear ERD structure for the ReptiMind database based on the refined 12-table schema.

Organize the ERD into four clusters: User & Pet Care, Monitoring & AI, Community, and Products & Orders. The ERD should be easy to explain in a report, with cluster names, table names, primary keys, foreign keys, and the most important fields.

【Explanation 3 / 正文可截图】

My goal in the third prompt was to turn the refined schema into a report-friendly ERD. The first two steps gave us the tables and relationships, but the diagram still needed a clear visual structure. We used the four-cluster output because it matched ReptiMind's product logic and made the final ERD easier to explain.

【Final Product Connection / 正文可截图】

The final database product was created from these three prompt steps. The table definition prompt produced the 12-table schema; the relationship refinement prompt produced the relationship mapping and major entity tables; and the ERD refinement prompt produced the four-cluster ERD used in the final product section.
