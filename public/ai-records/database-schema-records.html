Database Schema Deliverable

D2. Database Schema: Production Data Model

【Prompts Used / 正文可截图】

We are app developers building an AI-powered exotic reptile care app called ReptiMind. The current prototype uses mock JavaScript data, localStorage, and optional local JSON files, but we want to design a production-ready relational database schema for the app.

Please design a relational database schema for a future production version of ReptiMind. It should support users, reptile pet profiles, sensor readings, alerts, AI chat sessions, chat messages, community posts, community comments, shop products, orders, order items, and premium subscriptions.

Please include detailed tables, primary keys, foreign keys, important fields, and relationships. Also explain how the schema maps to the current prototype features.

【Raw AI Output / Appendix 可截图】

Although the current ReptiMind prototype does not use a real relational database, a production version should store data in structured tables. The existing prototype already implies several data entities: users, pets, sensor metrics, alerts, AI chat sessions, community content, shop products, and subscriptions.

The database schema can therefore be designed as a future-ready model. It documents how the app could scale from mock data and local JSON files into a real cloud-based business system. This is useful because the schema documents detailed tables, fields, and relationships before the app moves from prototype storage to a fully deployed database.

【Final Product / 正文可截图：Table Definitions】

The schema comprises 12 tables, each supporting a specific ReptiMind feature. The table below lists the tables, their purposes, and representative fields.

Table Description Fields
Users Stores user account, preferences, notification settings, and personalization data. user_id PK, username, email UNIQUE, password_hash, preferred_unit, push_enabled, created_at
Pets Stores each reptile profile owned by a user. pet_id PK, user_id FK, name, species, habitat, condition_label, activity_score, suggested_action
SensorReadings Stores time-series monitoring data for temperature, humidity, UVB, activity, water, and soil readings. reading_id PK, pet_id FK, temperature_c, humidity_percent, uvb_uvi, activity_score, recorded_at
Alerts Stores abnormal condition warnings generated by sensor readings or pet status. alert_id PK, pet_id FK, user_id FK, title, message, severity, source, is_read
ChatSessions Stores AI chat sessions for each user and selected pet. session_id PK, user_id FK, active_pet_id FK, title, assistant_avatar_id, created_at
ChatMessages Stores user and assistant messages within a chat session. message_id PK, session_id FK, role, content, model_name, created_at
CommunityPosts Stores reptile community posts and optional linked pet profiles. post_id PK, user_id FK, pet_id FK NULL, title, body, image_url, like_count
CommunityComments Stores replies and discussion under community posts. comment_id PK, post_id FK, user_id FK, body, created_at
Products Stores reptile care products such as sensors, tanks, food, hides, and cameras. product_id PK, name, category, description, price, stock_quantity, is_active
Orders Stores user purchase records and order status. order_id PK, user_id FK, total_amount, order_status, payment_status, created_at
OrderItems Stores products included in each order. order_item_id PK, order_id FK, product_id FK, quantity, unit_price
Subscriptions Stores premium plan, billing status, and AI feature access settings. subscription_id PK, user_id FK, plan_name, price, status, ai_chat_limit, device_history_days

After defining all tables, we identified the major entity tables that carry the core business data of ReptiMind. These tables are the main bridge between the current app prototype and a future production database.

Major Entity Cluster Main Role in ReptiMind
Users User & Pet Care Represents the pet owner account and stores app preferences.
Pets User & Pet Care Represents each reptile profile monitored by the app.
SensorReadings Monitoring & AI Stores the time-series care data used by dashboard, alerts, and AI context.
Alerts Monitoring & AI Stores abnormal events such as high temperature, low humidity, low activity, injury, or missing status.
ChatSessions / ChatMessages Monitoring & AI Stores AI conversations and links them to the user and selected pet.

【Refinement Prompt / 正文可截图】

The first schema is useful, but please refine it to better match the current ReptiMind prototype. The prototype includes custom pets, deleted built-in pet records, chat history, alert inbox, local fallback AI replies, product shop, and floating assistant sessions. Please explain which tables are essential for the current prototype and which tables are for future commercial scaling.

【Explanation of Refinements Made / 正文可截图】

After reviewing the first schema, we refined it into two levels. The essential prototype-level tables are Users, Pets, SensorReadings, Alerts, ChatSessions, and ChatMessages because they directly correspond to ReptiMind's dashboard, alert inbox, custom pet profiles, and AI chat history. The commercial expansion tables are Products, Orders, OrderItems, CommunityPosts, CommunityComments, and Subscriptions because they support future monetization, community engagement, and scaling.

This refinement makes the schema more realistic. It acknowledges that our current app uses mock data and local JSON files, while still showing how the same data objects can be migrated into a relational database for a production version.

【Final Product Connection / 正文可截图】

The schema maps directly to the final ReptiMind prototype: pet data in mockData.js maps to Pets and SensorReadings; generated alerts in App.jsx map to Alerts; chat sessions in Chat.jsx and server.js map to ChatSessions and ChatMessages; shop products map to Products; and profile/premium settings map to Users and Subscriptions.
